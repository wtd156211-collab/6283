# 稳定数据划分（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`：划分工具、命令行入口、期望核对与单文件 HTML 报告都从零写；
Python 3.13 标准库，不引第三方、不加构建步骤、不联网；自测用 `unittest`。

## 一、范围

做：读带类别标签的记录表，按「键 → 哈希 → 固定桶 → 份」把每条记录分到 `train` / `valid` / `test` 之一；
输出记录到份的映射与统计（各份比例、类别分布）；核对 `samples/expected/**`；生成样式与数据内联、双击即开的
单文件 HTML 报告。归属只由键、盐值与比例决定，与数据规模、行序、其它记录是否存在无关。

不做：分层抽样或按类别配额（类别分布只靠哈希的均匀性，达标即可）；键的规范化（大小写、首尾空白、Unicode
归一化一律不做）；跨数据集的状态文件或缓存；增量重划分与换盐值后的迁移；网络、数据库、多进程、多线程；
不修改 `samples/**`，除 `var/` 下的中间产物与报告外不写别的文件。

## 二、口径与公式

- 记录：一行一条，`键 TAB 类别标签`。两段都是非空字符串，不含 TAB 与控制字符；键可以重复，同一把键的所有行
  必须落在同一份。不做 trim：`a` 与 `a ` 是两把不同的键。
- 哈希：`v = sha256(盐值.utf8 + b"\x00" + 键.utf8)` 的前 8 字节按大端无符号整数；桶号 `b = v % 10000`，
  桶数固定 10000。
- 盐值：任意非空字符串（不含 NUL），按 UTF-8 编码。它决定同一把键落在哪个桶：换盐值等于整体重新划分，
  同一盐值下同一把键永远落在同一份。盐值只参与哈希，不进任何输出。
- 比例：`w1:w2:w3`，三个正整数、和为 100，依次对应固定的三份 `train`、`valid`、`test`；第 i 份占桶区间
  `[100*Σ_{j<i} wj, 100*Σ_{j<=i} wj)`（左闭右开）。
- 稳定性：归属是 `(盐值, 比例, 键)` 的纯函数。新增记录、删除记录、改变行序、换机器重跑，已有键的归属都不得
  改变，同一把键只能有一个份名。禁止用内置 `hash()`（逐进程随机化）、行号、出现次序、数据规模、随机数或
  其它记录的存在性来决定归属。
- 容差（验收用；期望文件本身仍逐字节比对）：数据 ≥ 1000 行时，每份实际行数占比与目标比例之差 ≤ 2.0 个百分点；
  全局行数 ≥ 200 的类别，其在某份中的占比与该类别的全局占比之差 ≤ 3.0 个百分点。低于门槛的不设容差。

## 三、数据结构与流水线

逐行处理、单遍完成，除唯一键集合与类别计数器外不保留历史：

1. 读一行 → 校验（恰好一个 TAB、两段非空、无控制字符）→ 得到 `(键, 类别标签)`。
2. 算桶号 `b` → 按比例找它落在第几份 → 得到份名。
3. `split` 按输入顺序写出映射行；`stats` 累加总行数、唯一键、每份行数、每类别行数、每类别×份行数。
4. 行序固定：映射按输入顺序；统计按 `total` → `split`（train/valid/test）→ `category`（类别标签按码点升序）；
   报告按 `samples/cases.tsv` 的行序。

## 四、输入输出与文件格式

- 数据文件：UTF-8 无 BOM，LF 换行（最后一行也带换行）；空行、CRLF、多一个 TAB 都算输入错误。
- 映射（stdout 与 `samples/expected/<名>.map.tsv`）：每行 `键 TAB 类别标签 TAB 份名`，行尾 `\n`。
- 统计（stdout 与 `samples/expected/<名>.stats.txt`）：`total TAB 行数 TAB 唯一键数`；
  `split TAB 份名 TAB 行数 TAB 占比`（占比为 `format(n*100/N, ".4f") + "%"`，0 行记 `0.0000%`）；
  `category TAB 标签 TAB 总行数 TAB train TAB valid TAB test`。
- 清单（TAB 分隔、LF 换行）：`samples/cases.tsv` 表头 `名 数据 盐值 比例 映射期望 统计期望`，路径相对
  `samples/`，映射期望写 `-` 表示只核对统计；`samples/stability.tsv` 表头 `名 数据A 数据B 盐值 比例 期望`。
- 稳定性期望（`samples/expected/<名>.stability.txt`）：`保留键`、`只在A`、`只在B`、`归属变化` 四行，值按唯一键
  计；核对时既比对这四个数，也逐键比较 A∩B 的份名。
- 命令行：

```text
python3 splithash.py split  <数据.tsv> <盐值> <比例>
python3 splithash.py stats  <数据.tsv> <盐值> <比例>
python3 splithash.py check  <样例根目录>
python3 splithash.py report <样例根目录> <输出.html>
```

`check` 读两份清单：样例的映射与统计逐字节比对期望文件，稳定性对逐键比较并核对四个计数；全对时 stdout 一行
`ok=11`（9 条样例 + 2 条稳定性），否则每处不符一行 `mismatch=<名>`、退出码 1。退出码：0 成功、1 有不符、
2 用法或输入错误（stderr 一行 `error: …`）。

- 报告：单个 HTML，样式与数据全部内联、无外链、`file://` 双击即开；按清单顺序分节，每节给样例名、行数、
  唯一键数、三份行数与占比条（条宽等于占比）、类别分布表与核对结论；顶部汇总样例数、总行数与通过数；
  不内联逐行映射。交付那份叫 `splithash.html`。

## 五、性能与验收口径

测试机 Windows + Python 3.13，单进程单线程；样例 9 份数据、2 组稳定性对。

1. 逐条核对：`check samples` 必须 `ok=11`。
2. 规模：`07-scale` 40 万行，`split` 与 `stats` 各 ≤ 10 秒（`time.perf_counter` 墙钟，不含解释器启动）。
3. 内存：处理 40 万行时 `tracemalloc` 峰值 ≤ 64 MiB；不许把全部行的解析结果留在内存里。
4. 确定性：同一输入连跑两遍逐字节相同；`PYTHONHASHSEED=0/1/2` 下相同；跑完 `samples/**` 不许有改动。
5. 稳定性：`05`、`06` 两组核对通过；同一盐值下任意子集/超集的交集键归属一致。
6. 比例与类别偏差：`07-scale` 满足第二节的容差。
7. 页面：报告无外链，分节数与清单一致，占比条宽度与统计里的占比一致。
8. 边界：`04-dup-keys` 的 120 行只有 36 把键，重复键必须落在同一份；`03-long-tail` 的 90 个单例类别不套用分布容差。
9. 只用标准库，自测用 `unittest`。

## 六、样例说明

`samples/data/*` 与两份清单里的期望一一对应，期望文件是原文（顺序敏感）。

| 名 | 场景与关键数字 |
| --- | --- |
| `01-balanced` | 类别均衡：4 类各 50 行，共 200 行 |
| `02-skewed` | 类别不均衡：210 / 60 / 30 行 |
| `03-long-tail` | 长尾：90 行分属 90 个只出现一次的类别，比例 90:5:5 |
| `04-dup-keys` | 重复键：120 行只有 36 把键，其中两把键跨两个类别 |
| `05-base` → `05-append` | 追加一批（同时清掉少量旧记录）：200 → 250 行，整体重排行序 |
| `06-full` → `06-dropped` | 删掉一批：240 → 192 行，留下的键归属不变 |
| `07-scale` | 40 万行、5 类不均衡，只核对统计，用来测时间与内存 |

`samples/notes.md` 是现场记录，只作背景，不作为口径。
